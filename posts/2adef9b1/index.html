Colossus — 通用列生成求解框架

A generic column generation framework for solving large-scale (mixed) integer linear programming problems.

作者：syuansheng（大连海事大学）

Colossus 是一个轻量、通用的列生成（Column Generation）求解框架。它将列生成算法的”骨架”与”问题相关的实现细节”彻底解耦：你只需要提供”怎么生成初始列、怎么建限制主问题、怎么求解定价子问题”这些与具体问题绑定的部分，剩下的列生成主循环、对偶提取、列池管理、迭代控制与结果输出全部由框架完成。

框架基于 Gurobi 求解器开发：主循环中限制主问题（Restricted Master Problem, RMP）由 Gurobi 求解；定价子问题（Pricing Subproblem）的求解算法则由用户自行设计，既可以是精确求解算法，也可以是启发式算法。

特性

  • 通用性强：只要你的问题能写成”限制主问题 + 定价子问题”的形式，就能用 Colossus 求解，例如切割下料问题（Cutting Stock）、车辆路径问题（VRP）、机组排班（Crew Scheduling）等大规模（混合）整数规划问题；
  • 定价策略灵活：支持纯启发式定价、纯精确解定价、以及”启发式为主 + 精确解兜底”的混合定价策略，混合策略下框架会自动在两者之间切换；
  • 内置列生成加速技巧：对偶平滑（dual smoothing，几何衰减系数）、mini-batch 提前终止、断点续算（本轮从上一轮停止的子问题继续求解）；
  • 自动同步列池与模型：列池中新增/删除的列会自动同步到 Gurobi 限制主问题模型中，无需手工维护；
  • 丰富的输出：控制台迭代表格、.result 结果文件、.col 列文件、.lp 模型文件、.ils 不可行性文件；
  • 依赖极少：仅依赖 gurobipy、numpy、wcwidth。

环境依赖与安装

  • Python 3.x（开发环境 3.12）；
  • Gurobi 求解器及 gurobipy（需要有效的 Gurobi 许可证，学生/学术用户可申请免费许可）；
  • numpy；
  • wcwidth（用于迭代表格中文字符宽度计算）；
  • （可选）matplotlib：仅示例程序末尾的画图代码使用，与框架本身无关。

安装依赖：

pip install gurobipy numpy wcwidth

本项目无需安装，将项目目录加入 Python 路径后即可导入：

from Colossus import ToolBox, Environment, Column, ColumnPool, Engine

快速开始：运行切割下料示例

项目自带一个完整的切割下料问题（Cutting Stock Problem, CSP）示例，其中主问题是”最小化使用的原材料根数”，定价子问题是一个背包问题（用动态规划精确求解 + 贪婪启发式求解）。

cd Colossus/examples
python CSP.py

运行后控制台会先打印 Engine 的配置信息，然后进入列生成迭代，输出类似如下的迭代表格：

其中各列含义：

使用指南：三步法

使用 Colossus 求解一个新问题只需要三步：实现接口 → 配置参数 → 运行引擎。

第一步：用 ToolBox 实现问题相关接口

ToolBox 是一个工具容器，通过 addTool(name, tool, *args, **kwargs) 把与具体问题绑定的可调用对象注册进去（支持绑定额外参数，注册后框架会按固定签名调用）。需要实现/注册的工具如下：

工具名 签名 必须 说明
generateInitialCols () -> ColumnPool ✅ 生成初始可行列，返回一个填充了初始列的 ColumnPool 对象
buildRestrictedMP (columnpool) -> gurobipy.Model ✅ 构建限制主问题（RMP）的 Gurobi 数学模型，接收初始列池，返回 Model 对象
updateAndSolveSP_Exact (y, fingerprint, omega_next_col) -> List[Column] 视定价策略 用精确解算法求解定价子问题，返回改善列列表
updateAndSolveSP_Heuristic (y, fingerprint, omega_next_col) -> List[Column] 视定价策略 用启发式算法求解定价子问题，返回改善列列表
coefficients_formatter (coefficients: list) -> str 可选 把 Column.coefficients 格式化为字符串，用于 .col 列文件的可读输出
modifyColumnPool (current_iter, columnpool) 可选 在每一轮迭代中（列生成循环内）对列池做自定义增删操作

各接口的详细约定：

1. generateInitialCols() —— 生成初始列

返回一个 ColumnPool 对象，其中每个 Column 至少需要设置：

  • omega：列在限制主问题中的索引（int），必须唯一；
  • tau：该列在限制主问题目标函数中的系数（float / int）；
  • coefficients：该列在各约束中的系数（list）。

初始列的 reduced_cost 建议保持 None。示例（切割下料问题中，为每种需求的原材料单独生成一列”只切这种料”的初始方案）：

def generateInitialCols():
    columnpool = ColumnPool()
    for omega in range(1, M + 1):
        column = Column()
        column.omega = omega
        column.tau = 1
        column.coefficients = [...]          # 与约束顺序对应的系数列表
        columnpool.addCol(column)
    return columnpool

2. buildRestrictedMP(columnpool) —— 构建限制主问题模型

返回一个 Gurobi Model。关键约束：

  • RMP 中每个初始列对应一个连续变量，变量名必须为 relaxed_variables_name[0] + '[' + str(omega) + ']' 的形式（例如 'labda[1]'），框架靠这个命名规则在模型中查找/删除列；
  • 建模建议：主问题尽量写成集覆盖（covering）或集划分（partitioning）的形式，约束用 >= 或 = 而不用 <=，这样限制主问题的对偶变量会更稳定，不容易剧烈波动；
  • 不需要在模型里添加以后会动态生成的列——那部分由框架自动完成。

示例：

def buildRestrictedMP(columnpool):
    rmp_model = Model()
    labda = rmp_model.addVars(
        [omega for omega in range(1, columnpool.col_num + 1)],
        vtype=GRB.CONTINUOUS, name='labda')          # 变量名自动为 labda[1], labda[2], ...
    rmp_model.setObjective(labda.sum('*'), sense=GRB.MINIMIZE)
    rmp_model.addConstrs(
        (quicksum(a[omega, i] * labda[omega] for omega in range(1, columnpool.col_num + 1)) >= d[i] for i in I),
        name='cons_rmp')
    return rmp_model

3. updateAndSolveSP_Exact / updateAndSolveSP_Heuristic —— 求解定价子问题

两个函数的签名一致，参数含义：

  • y：numpy.ndarray，限制主问题当前所有约束的对偶值（Pi），顺序与 buildRestrictedMP 中添加约束的顺序一致；
  • fingerprint：tuple，当前要定价的子问题的唯一标识，取自 Environment.fingerprint_lst；
  • omega_next_col：int，下一个新列的 omega 应当取的值（列池已维护好，直接使用即可）。

返回值：由改善列（Column 对象）构成的 list。找不到改善列时返回空列表。每个改善列至少需要设置：

  • omega：取传入的 omega_next_col；
  • reduced_cost：该列的检验数（reduced cost），对于最小化问题，负的 reduced cost 表示改善列；
  • tau：目标函数系数；
  • coefficients：约束系数列表。

示例（CSP 定价子问题 = 背包问题，用动态规划精确求解）：

def updateAndSolveSP_Exact(y, fingerprint, omega_next_col):
    improve_column_lst = []
    item_price, item_weight = {}, {}
    for i in I:
        item_price[i], item_weight[i] = y[i - 1], l[i]     # 用对偶值作为物品价格
    knapsack_solution, knapsack_obj = _solve_knapsack(L, item_set=I,
                                                      item_price=item_price,
                                                      item_weight=item_weight)
    if (1 - knapsack_obj) > -1e-6:                          # 无改善列
        return improve_column_lst
    column = Column()
    column.omega = omega_next_col
    column.reduced_cost = 1 - knapsack_obj
    column.tau = 1
    column.coefficients = list(knapsack_solution.values())
    improve_column_lst.append(column)
    return improve_column_lst

提示：框架本身不校验 reduced cost 的符号，是否”改善”由子问题函数自行判断（找不到改善列就返回空列表）。

4. coefficients_formatter(coefficients) —— 列文件格式化（可选）

当 Environment.col_file_output_on=True 时，框架会把每个生成的改善列写入 columns/Column[omega].col 文件，此时必须注册本工具，否则会打印提示且不写文件。工具接收 Column.coefficients（list），返回格式化后的字符串：

def coefficients_formatter(coefficients):
    return ''.join('a[{}]={}\n'.format(i, coefficients[i - 1]) for i in I)

5. modifyColumnPool(current_iter, columnpool) —— 自定义列池管理（可选）

每一轮迭代中，在”定价子问题产生改善列加入列池之后、把列池变更提交到 RMP 之前”被调用，用于实现自定义的列池维护策略（如固定列池大小、按 reduced cost 淘汰列等）。示例见 examples/CSP.py 中被注释掉的 modifyColumnPool。

第二步：配置 Environment

Environment 是一个 @dataclass 配置类，控制 Engine 的全部行为。前三个参数为位置参数（必填），其余均为带默认值的关键字参数：

参数 类型 默认值 说明
relaxed_variables_name list[str] （必填） 主问题中被线性松弛的变量名列表，第一个字符串对应的变量就是需要动态生成的列。建议各字符串首字母不同，避免 startswith 方法失效
relaxed_variables_type list[str] （必填） 被松弛变量原本的类型，'INTEGER' 或 'BINARY'（与 relaxed_variables_name 一一对应），列生成结束后框架会把它们恢复为原类型再求解
fingerprint_lst list （必填） 所有定价子问题的唯一标识（fingerprint）列表，引擎按顺序逐个求解子问题
barrier_method_on bool True 限制主问题是否使用内点法求解。推荐开启，内点法得到的对偶变量一般优于单纯形法
exact_solve_on bool True 是否用精确解算法求解定价子问题
heuristic_solve_on bool True 是否用启发式算法求解定价子问题
mini_batch_percent float 1.0 每轮迭代中，一旦有 round(mini_batch_percent * len(fingerprint_lst)) 个子问题产生了改善列，就提前结束本轮定价。只有一个子问题时该参数无意义
lp_file_ouput_on bool True 是否输出限制主问题的 .lp 模型文件（initial_rmp_model.lp / final_rmp_model.lp）
ilp_file_output_on bool True 限制主问题不可行时是否输出 Gurobi 不可行性文件（rmp_model.ils）
col_file_output_on bool True 是否将生成的改善列写入 columns/Column[omega].col 文件（需同时注册 coefficients_formatter）
result_file_output_on bool False 是否将最终求解结果写入 {engine_name}.result 文件
dual_alpha float 0 对偶平滑系数：y = alpha * y_上一轮 + (1 - alpha) * y_本轮，默认 0 表示不平滑。迭代中按几何衰减（每轮 alpha = 0.87096359 * alpha），约 100 轮后衰减到 0
truncate_threshold float 1e-6 相邻两轮限制主问题最优值之差的绝对值小于该阈值时，认为本轮没有改进
max_not_bertter float inf 限制主问题最优值连续 max_not_bertter 轮未改进时终止迭代（混合定价策略下会先切换为精确定价再判断）
max_time_limit float 3600.0 列生成迭代的总耗时上限（秒），超时强制终止
rmp_log_to_console bool False 是否在控制台展示 Gurobi 求解限制主问题的详细日志
table_header_language str 'ascii' 迭代表格表头语言：'ascii'（英文，任何环境严格对齐）或 'chinese'（中文，需终端将中文渲染为双宽）

第三步：创建 Engine 并运行

toolbox = ToolBox()
toolbox.addTool('generateInitialCols', generateInitialCols)
toolbox.addTool('buildRestrictedMP', buildRestrictedMP)
toolbox.addTool('updateAndSolveSP_Exact', updateAndSolveSP_Exact)
toolbox.addTool('updateAndSolveSP_Heuristic', updateAndSolveSP_Heuristic)
toolbox.addTool('coefficients_formatter', coefficients_formatter)
# toolbox.addTool('modifyColumnPool', modifyColumnPool)   # 可选

environment = Environment(['labda'], ['INTEGER'], [1])
environment.result_file_output_on = True

engine = Engine('csp_engine', environment, toolbox)
engine.runEngine()

创建 Engine 时会在控制台打印当前配置，运行前请先检查配置是否满足要求。运行结束后：

  • 最优目标值：engine.result.best_objective；
  • 总求解时长：engine.result.total_time；
  • 迭代历史：见下文 Result 对象。

框架运行流程

Engine.runEngine() 的内部流程如下：

  1. 构造初始列：调用 generateInitialCols() 得到初始列池；
  2. 构造限制主问题：调用 buildRestrictedMP(columnpool) 得到 RMP 的 Gurobi 模型；
  3. 列生成主循环（每轮迭代）：
    1. 求解限制主问题（Gurobi）；
    2. 提取约束对偶值 y，做对偶平滑处理；
    3. 依次求解定价子问题（按 fingerprint_lst 顺序，从 break_point 断点继续）：
      • 纯启发式：只调用 updateAndSolveSP_Heuristic；
      • 纯精确解：只调用 updateAndSolveSP_Exact；
      • 混合策略：先用启发式，满足切换条件后改用精确解兜底；
      • 满足 mini_batch_percent 提前终止条件时结束本轮定价；
    4. 将子问题返回的改善列加入列池，输出本轮迭代信息表格；
    5. 调用可选接口 modifyColumnPool 做自定义列池维护；
    6. 将列池变更自动提交到限制主问题模型（新增/删除变量）；
    7. 判断终止条件：
      • 连续 max_not_bertter 轮无改进 → 混合策略下切换为精确定价，否则终止；
      • 本轮所有子问题都找不到改善列 → 单定价方法直接终止；混合策略先切换精确，精确也找不到则终止；
      • 总耗时超过 max_time_limit → 终止；
  4. 求解最终主问题：把被松弛的变量恢复为 relaxed_variables_type 指定的整数/0-1 类型（此时列池中的全部列都在模型里），重置 Gurobi 参数为默认值，求解整数规划得到最终结果；
  5. 若 result_file_output_on=True，将结果写入 .result 文件。

API 参考

Column

Column 类用于存储限制主问题中单列的信息：

属性 类型 说明
omega int 列在限制主问题中的索引，必须唯一
reduced_cost float/None 列的检验数；初始列请设为 None
dummy_reduced_cost float/None 虚拟检验数（实验性想法：给某些列虚拟的低检验数以帮助进入最优基，默认 None）

ColumnPool 继承自 dict（omega -> Column），自动维护列池元信息：

属性/方法 说明

高级主题

定价策略：启发式与精确解切换

heuristic_solve_on 与 exact_solve_on 的组合决定定价策略：

  • 只开启发式：每轮只用启发式求解子问题，找不到改善列即终止（速度快，但可能提前收敛到次优）；
  • 只开精确解：每轮都用精确算法定价（慢，但收敛质量有保证）；
  • 两者都开（推荐）：先用启发式快速找改善列，当连续 max_not_bertter 轮无改进或启发式找不到改善列时，自动切换为精确解定价兜底；若精确解也找不到改善列，则终止。

对偶平滑（Dual Smoothing）

对偶变量直接使用容易在迭代间剧烈波动，导致生成的列质量不稳定。框架支持平滑：

y_本轮平滑 = alpha * y_上一轮 + (1 - alpha) * y_本轮原始
alpha 每轮按 0.87096359 几何衰减
  • 默认 dual_alpha=0（不平滑）；
  • 建议在子问题求解不稳定时开启，例如 dual_alpha=0.5；
  • 衰减策略保证后期平滑效应逐渐消失，不影响最终收敛。

mini-batch 提前终止

当子问题数量很多时，不必每轮把所有子问题都求解一遍。设置 mini_batch_percent（如 0.2）后，一旦本轮已有 round(mini_batch_percent * 子问题总数) 个子问题产生了改善列，就提前结束本轮定价；下一轮从断点 break_point 继续求解剩余子问题，保证每个子问题最终都会被定价到。

自定义列池管理

注册 modifyColumnPool(current_iter, columnpool) 后，每轮迭代都会在”改善列入池后、提交模型前”调用它。可以在此实现列池瘦身（如固定列池大小、剔除长期不在最优基的列），注意：

  • 删除列请使用 columnpool.delColByOmega(omega)，框架会自动同步到模型；
  • 不要删除当前轮次刚加入的列（可检查 columnpool._memory_change['omega_cols_added']）。

建模建议

  • 主问题尽量写成集覆盖 / 集划分形式（约束为 >= / =），对偶变量更稳定；
  • 限制主问题模型中的列变量名必须严格遵循 relaxed_variables_name[0] + '[' + omega + ']' 格式；
  • relaxed_variables_name 各字符串首字母不要相同，避免 startswith 误匹配；
  • 定价子问题的系数顺序（coefficients）必须与 buildRestrictedMP 中添加约束的顺序一致，因为 y 的顺序就是约束的顺序。
